# 08. 开发顺序与落地清单

本文不再描述早期“先做真实下载器、先补 `gradlew`”那种旧顺序，而是基于当前工程现状给出新的开发优先级。

## 1. 当前已完成

- A / A2：多终端 UI 基调与统一按钮状态语义（早期大屏稿已扩展到手机、平板和桌面级大屏）
- C1 ~ C14：下载、安装、升级、任务中心、状态基座
- R1：真实下载器、下载源治理、环境切换
- R2：真实安装器、安装会话、系统确认分发
- D：统一数据层第一轮收口
- M1 ~ M15：多模块与 feature module 化
- M16 / M17：工程治理、资源命名、文档归并
- P1 基础硬化：目录条件请求缓存、可选车载 provider 接缝、聚合层关键测试
- P2 生产硬化：系统边界输入校验+测试、下载基地址外化、XML 全量 @dimen/ 化、策略从 config 读取、开发者工具扩展、Mapper 测试、Android 设备回归清单、后端/平台适配器验收标准
- P2 运营治理前置：目录治理字段支持灰度、黑白名单、隐藏/下架和回滚版本；页面曝光、主按钮点击、下载/安装/升级结果均已本地事件落盘
- P2 安全收口：目录标识/重复项/签名摘要校验、下载任务 canonical path containment、APK 包名/版本/签名预检和安装后 PackageManager 事实核对

## 2. 建议的下一阶段顺序

### P0：真实设备联调

- [ ] 在真实设备上验证下载 -> 安装 -> 升级全链路
- [ ] 记录不同 Android 版本/ROM 的系统确认页与安装回调差异；车载 OEM 作为可选子集单独标记
- [ ] 补充安装失败、升级失败的真机回归记录
- [ ] 固化一份设备侧回归清单

### P1：真实目录 API 接入

- [ ] 把当前目录链路接入真实后端地址
- [ ] 根据后端要求补充认证头、灰度头或签名头
- [ ] 对齐目录字段、错误码和缓存策略
- [ ] 正式目录为每个 APK 提供正数 `versionCode` 和至少一个 `signerCertificateSha256`
- [ ] 验证 304、回源失败、缓存损坏等降级路径

### P1：平台策略解耦与可选车载信号接入

- [ ] 增加平台能力开关；非车载发行目标不得因缺少驻车信号阻断安装/升级
- [ ] 只有车载发行目标才用真实 OEM provider 替换当前 `StaticVehicleStateSignalProvider`
- [ ] 车载专项按需对接驻车、点火、电源或前后台限制信号
- [ ] 明确信号抖动、延迟、缺失时的策略刷新和回退行为
- [ ] 补充可选 OEM 信号映射与专项测试

### P2：上线前治理与运营能力

- [x] 目录侧灰度发布、黑白名单、隐藏/强制下架、回滚版本字段已接入客户端过滤与展示语义
- [ ] 安装失败与升级失败归因看板
- [x] 曝光、主动作点击、下载/安装/升级结果埋点已落本地事件日志
- [x] 面向后端、Android 设备和可选 OEM 的分层联调验收文档已输出，剩余为真实团队联调填数

## 3. 每次迭代的检查清单

- [ ] 是否破坏了 7 个业务模块边界
- [ ] 是否绕过了 `StateCenter`
- [ ] 是否把业务逻辑写回了 Fragment / Activity
- [ ] 是否直接操作数据源而没有经过业务层
- [ ] 是否在 `app` 壳层新增了本应属于 `business / data / core` 的逻辑
- [ ] 是否引入了新的资源命名和字符串治理倒退
- [ ] 是否绕过了目录标识校验、下载路径 containment 或 APK 身份校验

## 4. 当前推荐分工

- 页面与交互：`feature-* + common`
- 下载与安装真实能力：`core + business`
- 数据层与本地存储：`data`
- 状态与策略：`business/domain/state + business/domain/policy`
- 壳层装配与系统桥接：`app`
- 文档维护：`docs`
