# 06. 工程演进与当前阶段判断

## 1. 这份文档现在怎么读

这个编号位文档原本来自早期的 `A ~ C13` 阶段说明，但项目已经继续向后演进。  
因此这份文档不再只描述 A、C 阶段，而是用它来解释整个工程从早期 UI 骨架走到当前 `R1 / R2 / D / M1 ~ M17` 的脉络。

## 2. 早期阶段做了什么

### A：多终端 UI 基调（早期以大屏/车机设计稿为参考）

完成了卡片化视觉基调、响应式导航结构和基础页面样式，为手机、平板、桌面级大屏及可选车载横屏上的首页、详情页、任务中心打下基础。

### A2：统一按钮与状态标签体系

把页面里的主按钮、状态标签和交互风格抽成统一语义，减少页面各自为战。

### C1 ~ C14：主链路业务骨架

这一阶段把下载、安装、升级、任务中心和状态管理从页面逻辑里抽出来，形成了后面 7 个业务模块的基础形态。

关键产物包括：

- 下载任务记录与恢复
- 安装任务展示
- 升级任务编排
- 统一任务中心视图
- 失败码与重试逻辑
- 统计、筛选、空态、批量操作

## 3. 后续阶段把工程推到了哪里

### R1：真实下载器

把下载能力从模拟流程推进到真实 HTTP 下载、Range、分片、校验、元数据恢复。

### R2：真实安装器

把安装链路推进到 `PackageInstaller.Session`、安装会话落盘、系统确认分发、安装中心 Session 视角。

### D：统一数据层

把本地落盘访问逐步收敛到 `LocalStoreFacade` 和结构化实体上，不再完全依赖散落 JSON 和偏好读写。

### M1 ~ M15：多模块与 feature 化

把工程拆成 `app / common / core / data / business / feature-*` 结构，并完成第一轮资源、binding、依赖方向收口。

### M16 / M17：工程治理

统一文档、依赖版本、资源命名和脚手架基线，降低后续继续演进时的噪音。

## 4. 当前成熟度判断

当前工程的成熟度可以概括为：

**跨平台产品的 Android 主链路已通，真实能力 R1-R6、P1/P2 生产硬化、P3 代码重构和平台边界 P6 已完成；商店目录具备 HTTP/条件请求缓存/资源回退、输入校验和 `supportedPlatforms` 解析，下载路径具备越界防护，安装链路具备 APK 包名/版本/签名预检与安装后事实核对；截至 2026-07-31，45 份测试报告共 246 个单元测试为 0 失败，当前进入真实生产 API、签名配置和 Android 设备矩阵验收阶段。**

已经不是：

- 只有页面壳子
- 只有模拟下载安装
- 只有单 app 包结构
- 只有 fake 数据源

也还不是：

- 接入真实远端 API
- 全平台验证完成的交付版
- 生产平台策略动态化完全体（远端规则，以及车载发行可选的 OEM 驻车/车况真值）

## 5. 当前最值得关注的真实边界

- 远端目录已具备 HTTP/条件请求缓存/资源回退链路和非法目录拒绝能力，但仍未接入提供 `versionCode`、签名摘要的真实 API
- `DefaultPolicyCenter` 已支持网络/存储实时信号，并通过 `vehicleInstallPolicyEnabled` 把通用平台与可选车载驻车限制解耦；`VehicleStateSignalProvider` 仅作为可选车载接缝
- 目录和业务层已接入 `supportedPlatforms/currentPlatform`，其他平台安装包在 UI 动作和下载/安装/升级执行入口均会被拒绝
- 安装链路需要覆盖 Android 版本/ROM 设备矩阵；其他产品平台还需各自的安装器适配
- 通用剩余项是真实 API、生产签名、观测上传和设备矩阵验证；OEM 车况只属于车载发行目标的外部依赖

## 6. 下一步建议

1. **P0 设备联调** — 真实设备上验证下载→安装→升级全链路
2. **P1 远端数据接入** — 把当前回退链路接到真实 API，并补鉴权/缓存治理
3. **P1 生产发布配置** — 接入生产目录/CDN、认证和正式签名，并固化配置自检
4. **P2 外部联调** — 推进真实 API 和 Android 设备矩阵验证；车载发行目标另行执行 OEM 专项
