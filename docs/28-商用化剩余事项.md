- 第一性原理审计后的 lint 阻断已修复，`testDebugUnitTest`、`compileDebugKotlin`、`:app:assembleDebug`、`lintDebug`、`:app:assembleRelease` 最近一次验证通过。
- 换机接手总览已补充到 `docs/29-换机接手与当前进度总览.md`，用于说明当前同步基线、已完成能力和未完成外部依赖。

- 内置 `raw/app_store_catalog.json` 已补充 `asset://` 形态的图标、头图和截图地址占位。
- 下载、安装、升级链路已有的 `EventTracker.track(...)` 已接入本地事件落盘文件，开发者设置页可查看事件条数、文件大小并清理事件日志；后续可基于同一事件源接上传服务。

- 可选车载 OEM 车况已支持广播型接入，配置广播 action 和 extra 后可替换静态兜底车况；驻车/电源 extra 支持 Boolean、数字和常见字符串值（如 `P`、`parked`、`drive`、`0/1`）。
- 应用图标、详情头图和详情截图已支持 `asset://`、`file://`、`http(s)://` 图片加载，失败时回退到文本兜底。
- 目录治理字段已接入：`listingState`、`rolloutPercent`、`allowedChannels`、`blockedChannels`、`rollbackVersion` 可控制灰度、黑白名单、隐藏/下架和回滚版本。
- 目录已接入 `versionCode` 与 `signerCertificateSha256`；安装前校验 APK 包名、版本和签名证书，安装后以 PackageManager 事实收口。
- `appId`、`packageName` 和下载任务 ID 已增加白名单、重复项拒绝与 canonical path containment。
- 页面曝光、应用主动作点击、下载/安装/升级开始与结果已写入本地事件日志，开发者设置页可查看和清理日志。
- Release 构建固定使用 PROD，忽略持久化的 Debug/LOCAL_SIM 环境；release raw 目录为安全空目录，未注入生产地址时不会回退到 example 或 `10.0.2.2`。
- `VersionedJsonStore` 已按规范化文件路径共享进程锁；安装冷启动会补记已完成事实、放弃遗留平台 Session 并把未完成记录转为可重试。
- GitHub Actions 工作流已覆盖与本地相同的 JDK 17 验证链和 APK/报告归档，首次 hosted runner 运行已成功。
- 通用平台与可选车载驻车策略已解耦；目录和业务动作已接入 `supportedPlatforms/currentPlatform`。

## 2. 外部配置入口

后端目录与 APK 源：

- `CARAPPSTORE_CATALOG_DEV_URL`
- `CARAPPSTORE_CATALOG_TEST_URL`
- `CARAPPSTORE_CATALOG_PROD_URL`
- `CARAPPSTORE_DOWNLOAD_DEV_BASE_URL`
- `CARAPPSTORE_DOWNLOAD_TEST_BASE_URL`
- `CARAPPSTORE_DOWNLOAD_PROD_BASE_URL`
- `CARAPPSTORE_CATALOG_AUTH_HEADER`
- `CARAPPSTORE_CATALOG_AUTH_VALUE`

可选车载 OEM 广播车况（非车载发行不配置）：

- `CARAPPSTORE_OEM_VEHICLE_ACTION`
- `CARAPPSTORE_OEM_PARKING_EXTRA`
- `CARAPPSTORE_OEM_POWER_EXTRA`

Release 签名：

- `CARAPPSTORE_RELEASE_STORE_FILE`
- `CARAPPSTORE_RELEASE_STORE_PASSWORD`
- `CARAPPSTORE_RELEASE_KEY_ALIAS`
- `CARAPPSTORE_RELEASE_KEY_PASSWORD`

这些值可以通过系统环境变量提供，也可以用 Gradle 参数提供，例如：

```bash
./gradlew :app:assembleRelease \
  -PCARAPPSTORE_RELEASE_STORE_FILE=/secure/carappstore.jks \
  -PCARAPPSTORE_RELEASE_STORE_PASSWORD=*** \
  -PCARAPPSTORE_RELEASE_KEY_ALIAS=carappstore \
  -PCARAPPSTORE_RELEASE_KEY_PASSWORD=*** \
  -PCARAPPSTORE_CATALOG_PROD_URL=https://catalog.example.com/carappstore/catalog.json \
  -PCARAPPSTORE_DOWNLOAD_PROD_BASE_URL=https://download.example.com/carapps
```

## 3. 后端目录新增字段

每个应用对象可以额外提供：

- `iconUrl`
- `bannerUrl`
- `screenshotUrls`
- `apkUrl`
- `checksumType`
- `checksumValue`
- `versionCode`
- `signerCertificateSha256`
- `sourcePolicy`：`DIRECT_HTTP`、`MOCK` 或 `FALLBACK_SIMULATED`
- `listingState`：`ACTIVE`、`HIDDEN`、`REMOVED` 或 `ROLLBACK`
- `rolloutPercent`
- `allowedChannels`
- `blockedChannels`
- `rollbackVersion`

客户端读取详情时优先使用目录返回的 APK 元数据；没有返回时才回退到 `DownloadSourceCatalog` 按环境基地址拼接。
客户端读取目录时会先应用运营治理：隐藏/下架条目不展示，灰度和 channel 黑白名单按当前请求头 channel 过滤，回滚条目会使用回滚版本展示并关闭升级态。

## 4. 仍需真实外部值才能最终验收

- 后端目录正式地址、鉴权头、灰度头和错误码约定。
- APK 源正式域名、文件命名、包体大小、checksum、versionCode 和签名证书 SHA-256 摘要。
- 可选车载发行所需的 OEM 车况/电源/前后台限制 SDK 或系统广播协议；通用发行不依赖该项。
- 生产签名 keystore、alias 和密码，由环境变量注入构建。
- 埋点上传服务地址、批量策略、隐私合规字段和告警看板；本地事件源已具备，上传服务仍需外部平台。

## 5. 商用前验收顺序

1. 接后端目录 API，校验 `supportedPlatforms`、APK 身份字段、缓存、304 和回退链路。
2. 接真实 APK CDN、图片源与认证配置，并复查生产缓存和失败兜底。
3. 配置 release 签名环境变量，生成签名 release APK。
4. 在手机、平板和桌面级大屏的 Android 设备矩阵上验证安装、升级、用户确认页、安装回调和失败恢复。
5. 接埋点上传、崩溃收集、失败归因和运营灰度能力。
6. 仅当发行目标包含车载设备时，接 OEM `VehicleStateSignalProvider` 并执行驻车/行车和车载 ROM 专项。
