# 多端 UI 框架设计

> 目标：参考 `docs/设计` 下 8 张多设备设计稿，先建立同一业务页面在手机、平板、车机/桌面上的响应式壳层，再逐页重做内容区。

## 断点与布局

- 手机：默认 `layout/activity_main.xml`，顶部品牌区 + 横向导航 + 单列内容区，适合竖屏和窄屏。
- 平板：`layout-sw600dp/activity_main.xml`，左侧导航栏 + 右侧内容区，减少顶部占用，内容区可承载双列卡片。
- 车机/桌面：`layout-sw900dp-land/activity_main.xml`，左侧宽导航 + 中央主内容 + 右侧任务摘要栏，适合横屏大屏和远距离阅读。

## 壳层约束

- 三套布局保持同一组 ViewBinding id：`tvTitle`、`tvSubtitle`、`btnNavHome`、`btnNavSearch`、`btnNavDownload`、`btnNavUpgrade`、`btnNavInstall`、`btnNavMyApps`、`btnNavDebug`、`fragmentContainer`。
- `MainActivity` 不感知设备类型，由 Android 资源限定符自动选择布局。
- 业务 Fragment 继续只负责内容区，不直接处理整屏导航结构。

## 下一步页面改造顺序

1. 首页：应用推荐、最近使用、搜索入口、应用卡片响应式栅格。
2. 下载管理：下载/安装任务聚合、批量操作、状态筛选。
3. 升级管理：可升级列表、失败重试、批量升级。
4. 详情页：应用头图、版本信息、权限/兼容性、主操作按钮。

## 设计方向

- 手机：信息密度低，单列卡片，主操作按钮显眼。
- 平板：双列/主从布局，左侧稳定导航，列表和详情可并排扩展。
- 车机/桌面：大字号、大触控目标、状态摘要常驻，降低驾驶场景里的阅读和操作成本。
