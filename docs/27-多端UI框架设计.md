# 多端 UI 框架设计

> 目标：参考 `docs/设计` 下 8 张多设备设计稿，先建立同一业务页面在手机、平板、车机/桌面上的响应式壳层，再逐页重做内容区。

## 断点与布局

- 手机：默认 `layout/activity_main.xml`，顶部品牌区 + 主内容区 + 底部 4 项导航，适合竖屏和窄屏。
- 平板：`layout-sw600dp/activity_main.xml`，顶部品牌区 + 宽内容区 + 底部 4 项导航，内容区承载双列卡片。
- 车机/桌面：`layout-sw900dp-land/activity_main.xml`，左侧完整导航菜单 + 中央主内容 + 右侧任务摘要栏，适合横屏大屏和远距离阅读。
- 首页内容也按端区分：手机/平板使用竖向瀑布流首页；车机/桌面使用 `feature-home/layout-sw900dp-land/fragment_home.xml` 的横向信息面板布局。

## 壳层约束

- 三套布局保持同一组 ViewBinding id：`tvTitle`、`tvSubtitle`、`btnNavHome`、`btnNavSearch`、`btnNavDownload`、`btnNavUpgrade`、`btnNavInstall`、`btnNavMyApps`、`btnNavDebug`、`fragmentContainer`。
- 手机和平板只露出 4 个底部主入口：首页、游戏、软件、我的；安装、升级、下载管理等深层管理入口由页面内容和车机/桌面完整菜单承载。
- 车机/桌面保留完整导航密度：首页、游戏、软件、分类、排行、必备、活动、我的，下载管理固定在侧栏底部，并常驻任务摘要。
- `MainActivity` 不感知设备类型，由 Android 资源限定符自动选择布局。
- 业务 Fragment 继续只负责内容区，不直接处理整屏导航结构。

## 当前页面状态

- 首页、下载管理、升级管理、详情页已具备手机/平板/车机桌面资源限定符下的主要响应式结构。
- 车机/桌面布局已补齐 `layout-sw900dp-land` 变体，主壳层、首页和管理页面可以在横屏大屏上保持导航和任务摘要稳定。
- 后续 UI 工作重点不是重新搭页面，而是真机像素验收、目标车机触控距离校准、真实图片素材接入后的裁切/占位检查。

## 下一步 UI 验收顺序

1. 目标车机横屏：检查侧边导航、任务摘要、首页横向信息面板是否在真实分辨率下稳定。
2. 平板竖/横屏：检查双列内容、底部导航和详情页媒体区域。
3. 手机窄屏：检查长标题、按钮文案、任务状态和空态是否溢出。
4. 真实媒体资源：接真实 icon/banner/screenshot 后复查裁切、失败兜底和缓存行为。

## 设计方向

- 手机：信息密度低，单列卡片，主操作按钮显眼。
- 平板：双列/主从布局，但仍使用底部 4 项导航，避免把桌面侧边栏硬塞进移动设备。
- 车机/桌面：大字号、大触控目标、左侧完整菜单和状态摘要常驻，降低驾驶场景里的阅读和操作成本。
