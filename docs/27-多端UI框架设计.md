# 跨平台 UI 与多终端框架设计

> 目标：参考 `docs/设计` 下 8 张多设备设计稿，先建立同一业务页面在紧凑、中等和扩展窗口上的响应式壳层，再逐页重做内容区。车载横屏只是扩展窗口的可选适配场景。

## 断点与布局

- 手机：默认 `layout/activity_main.xml`，顶部品牌区 + 主内容区 + 底部 4 项导航，适合竖屏和窄屏。
- 平板：`layout-sw600dp/activity_main.xml`，顶部品牌区 + 宽内容区 + 底部 4 项导航，内容区承载双列卡片。
- 桌面级大屏/扩展窗口：`layout-sw900dp-land/activity_main.xml`，左侧完整导航菜单 + 中央主内容 + 右侧任务摘要栏，适合横屏大屏；车载目标可在此基础上追加远距离阅读和车规触控校准。
- 首页内容按窗口区分：手机/平板使用竖向瀑布流首页；扩展窗口使用 `feature-home/layout-sw900dp-land/fragment_home.xml` 的横向信息面板布局。

## 壳层约束

- 三套布局保持同一组 ViewBinding id：`tvTitle`、`tvSubtitle`、`btnNavHome`、`btnNavSearch`、`btnNavDownload`、`btnNavUpgrade`、`btnNavInstall`、`btnNavMyApps`、`btnNavDebug`、`fragmentContainer`。
- 手机和平板只露出 4 个底部主入口：首页、游戏、软件、我的；安装、升级、下载管理等深层管理入口由页面内容和扩展窗口完整菜单承载。
- 扩展窗口保留完整导航密度：首页、游戏、软件、分类、排行、必备、活动、我的，下载管理固定在侧栏底部，并常驻任务摘要。
- `MainActivity` 不感知设备类型，由 Android 资源限定符自动选择布局。
- 业务 Fragment 继续只负责内容区，不直接处理整屏导航结构。

## 当前页面状态

- 首页、下载管理、升级管理、详情页已具备手机/平板/扩展窗口资源限定符下的主要响应式结构。
- 扩展窗口布局已补齐 `layout-sw900dp-land` 变体，主壳层、首页和管理页面可以在横屏大屏上保持导航和任务摘要稳定。
- 后续 UI 工作重点不是重新搭页面，而是 Android 设备矩阵像素验收、窗口缩放/横竖屏校准和真实图片素材接入后的裁切/占位检查；车载目标另做触控距离专项。

## 下一步 UI 验收顺序

1. 手机窄屏：检查长标题、按钮文案、任务状态和空态是否溢出。
2. 平板竖/横屏：检查双列内容、底部导航和详情页媒体区域。
3. 桌面级大屏/扩展横屏：检查侧边导航、任务摘要和首页横向信息面板在真实分辨率及窗口变化下是否稳定。
4. 可选车载横屏：在发行目标包含车载设备时，追加远距离阅读、触控目标和驾驶场景限制专项。
5. 真实媒体资源：接真实 icon/banner/screenshot 后复查裁切、失败兜底和缓存行为。

## 设计方向

- 手机：信息密度低，单列卡片，主操作按钮显眼。
- 平板：双列/主从布局，但仍使用底部 4 项导航，避免把桌面侧边栏硬塞进移动设备。
- 桌面级大屏/扩展窗口：更高信息密度、左侧完整菜单和状态摘要常驻；可选车载主题再增加大字号、大触控目标和驾驶场景限制。
