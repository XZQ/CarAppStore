# 33. 生产发布配置与 Android 设备验证基线

> 更新时间：2026-09-12
> 范围：当前仓库交付的 Android 客户端。其他软件平台应在各自客户端建立同等级别的发布门禁；可选车载 OEM 验收不是通用版本前提。

## 1. 仓库内已经闭环的发布门禁

- `verifyProductionConfig` 在构建前校验生产目录、APK CDN、认证模式和 Release 签名。
- 目录与 CDN 必须是非 localhost、非 example 的绝对 HTTPS 地址；CDN 基地址不得携带 query 或 fragment。
- 目录必须显式选择 `PUBLIC`（公开只读目录）或 `RUNTIME`（运行时短期 Bearer 凭证）。
- CDN 必须显式选择：
  - `RUNTIME`：每次 HEAD、GET 和 Range 请求读取内存中的短期凭证；认证请求禁止自动重定向。
  - `SIGNED_URL`：由目录返回短时签名 HTTPS URL，不附加固定认证值。
- 旧的 `*_AUTH_HEADER` / `*_AUTH_VALUE` 配置不再支持；令牌不得通过构建配置注入。接入约定与尚未完成的后端工作见 [运行时短期鉴权接入](35-运行时短期鉴权接入.md)。
- Release keystore 必须可读，store password 必须能打开，alias 必须存在，key password 必须能解锁私钥。
- `assembleProductionRelease` 只在上述门禁通过后构建 Release APK。
- `tools/production/verify-production-readiness.ps1` 还会用 Android SDK `apksigner` 验证最终 APK 的签名。

普通 `:app:assembleRelease` 保留为无密钥 CI/工程诊断入口，不能替代生产发布命令。

## 2. 配置方法

签名信息优先由 CI Secret/组织密钥管理提供；目录/CDN 地址与模式通过发布配置提供，访问令牌只在运行时由认证服务签发。仅在受控本机临时联调时复制签名及模式模板，绝不能提交真实签名密码：

```powershell
Copy-Item .\tools\production\production.env.example .\tools\production\production.env
```

填写 `production.env` 后运行：

```powershell
$env:JAVA_HOME="<JDK 17 path>"
.\tools\production\verify-production-readiness.ps1
```

也可以直接通过 CI Secret、系统环境变量或 Gradle `-P` 注入同名键。Gradle 属性优先于环境变量。

| 配置 | 要求 |
|---|---|
| `CARAPPSTORE_CATALOG_PROD_URL` | 生产目录 HTTPS URL |
| `CARAPPSTORE_DOWNLOAD_PROD_BASE_URL` | 生产 APK CDN HTTPS 基地址 |
| `CARAPPSTORE_CATALOG_AUTH_MODE` | `PUBLIC` 或 `RUNTIME` |
| `CARAPPSTORE_DOWNLOAD_AUTH_MODE` | `RUNTIME` 或 `SIGNED_URL` |
| `CARAPPSTORE_RELEASE_STORE_FILE` | 仓库外的绝对 keystore 路径 |
| `CARAPPSTORE_RELEASE_STORE_PASSWORD` | 通过 Secret 管理 |
| `CARAPPSTORE_RELEASE_KEY_ALIAS` | Release 私钥别名 |
| `CARAPPSTORE_RELEASE_KEY_PASSWORD` | 通过 Secret 管理 |

客户端内的值可以被 APK 使用者提取，因此 BuildConfig 不再包含认证值。`RUNTIME` 模式需要先完成 docs/35 的登录/刷新接入；当前仓库提供的是内存凭证和 HTTP 接线，没有已验证的生产认证接口。

## 3. 自动验证与外部验收的边界

仓库门禁可以证明配置格式、认证接线、keystore 可用和 APK 已签名，但不能替代真实生产系统：

- 正式域名、证书链、401/403、缓存、304、灰度和错误码必须与真实目录服务联调。
- CDN 的 HEAD、GET、Range、断点续传、checksum 和签名 URL 过期行为必须对真实 APK 执行。
- 生产签名证书摘要必须由发布负责人独立核对并进入签名备份/轮换流程。
- 没有真实设备报告时，安装确认页、未知来源权限、ROM 回调和升级覆盖行为一律视为 `NOT RUN`，不得写成 PASS。

## 4. Android 设备矩阵基线

| 组别 | 必测环境 | 自动证据 | 手工证据 |
|---|---|---|---|
| 最低版本手机 | API 26-28 | 设备事实、APK SHA-256、安装结果 | 下载/安装/升级、权限确认、冷启动恢复 |
| 主流手机 | API 30-34 | 同上 | 同上，补后台限制与弱网 |
| 当前系统手机 | API 35-36 | 同上 | 当前系统安装行为、通知/权限和边到边显示 |
| 平板 | 真实 `sw600dp` 设备 | 分辨率、density、构建指纹 | 双列布局、旋转、多窗口、安装确认 |
| 桌面级大屏/扩展窗口 | `sw900dp-land` Android 环境 | 分辨率、density、构建指纹 | 侧栏、右侧任务摘要、键鼠/触控 |
| 可选车载 | 目标 OEM ROM | 车机与协议版本 | 驻车/行车、OEM 回调；非车载版本填 N/A |

连接且只连接一台已授权设备后生成基线：

```powershell
.\tools\device-validation\collect-android-baseline.ps1 `
  -ApkPath .\app\build\outputs\apk\release\app-release.apk
```

需要由脚本安装时显式加 `-Install`。报告写入被 Git 忽略的 `build/device-validation/`，然后由 QA 按 `docs/25-真机回归测试清单.md` 执行 44 项手工回归并把报告、日志和截图归档到发布系统。

## 5. 当前状态

- 仓库侧具备生产模式校验、短期凭证 HTTP 接线、签名 URL 下载、签名校验、CI 临时签名验证和设备证据采集入口。
- 真实生产 URL 和 keystore 由发布环境提供；令牌签发、刷新和设备联调尚需外部完成，访问令牌不再由构建环境注入。
- 本基线建立时 `adb devices -l` 没有已授权设备，因此没有声称任何真机测试已通过；下一次发布必须按本页与 docs/25 补齐证据。
