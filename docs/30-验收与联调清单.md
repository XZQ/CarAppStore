# 30. 验收与联调清单（docs/25 + docs/26 合并梳理）

> 来源：`docs/25-真机回归测试清单.md`、`docs/26-后端与OEM验收标准.md`
> 用途：发布前对外（后端 / OEM / QA）对齐的合并验收与联调清单，可直接勾选跟踪。
> 当前进度基线：仓库内主链路已通、184 单测全绿；本清单剩余项均为**外部资源或真机验收**，非仓库结构缺口。

## 0. 总览与排期

| 阶段 | 时间 | 主要工作 | 交付物 |
|------|------|----------|--------|
| 第 1 周 | 第 1-5 天 | 后端目录 API 联调 | 目录可加载、缓存可命中、回退可工作 |
| 第 2 周 | 第 6-10 天 | OEM 车况信号联调 | 信号可接入、策略可联动、抖动可容忍 |
| 第 3 周 | 第 11-15 天 | 真机全链路验证 | 下载-安装-升级全链路通过回归清单 |
| 第 4 周 | 第 16-20 天 | 灰度和稳定性验证 | 灰度头可切换、长时间运行不崩溃 |

## 一、后端目录 API 联调清单（doc26 §1）

### 1.1 接口对接要求（后端提供）
- [ ] 目录接口正式地址（对应 `DownloadEnvironmentConfig.catalogEndpointUrl`）
- [ ] 鉴权方案 / 灰度头定义（对应 `DownloadEnvironmentConfig.catalogRequestHeaders`）
- [ ] 返回字段说明与错误码说明
- [ ] 缓存策略约定（ETag / Last-Modified / Cache-Control）
- [ ] 降级策略约定（空目录、部分字段缺失、非 200 返回）

### 1.2 字段对齐（后端返回对象须包含，DTO：`AppCatalogItemResponse`）
必填字段（缺失则后端不应返回该条目）：
- [ ] `appId`（稳定唯一标识）
- [ ] `packageName`（Android 包名）
- [ ] `name`（显示名称）
- [ ] `versionName`（如 "1.2.3"）
- [ ] `versionCode`（正整数，必须与 APK archive 一致）
- [ ] `signerCertificateSha256`（至少一个 64 位十六进制 SHA-256 摘要）

可选字段（缺失时客户端不崩溃、对应位置留空）：
- [ ] `description` / `category` / `editorialTag` / `recommendedReason`
- [ ] `searchKeywords`（**必须是字符串数组**，不能是逗号分隔单串）
- [ ] `developerName` / `ratingText` / `sizeText` / `lastUpdatedText`
- [ ] `compatibilitySummary` / `permissionsSummary` / `updateSummary`
- [ ] `latestVersion` / `hasUpgrade`(Boolean) / `changelog`
- [ ] `listingState`：`ACTIVE` / `HIDDEN` / `REMOVED` / `ROLLBACK`
- [ ] `rolloutPercent`(0-100，按 appId 稳定分桶)
- [ ] `allowedChannels` / `blockedChannels`（List<String>）
- [ ] `rollbackVersion`（`ROLLBACK` 状态使用）

结构约束：
- [ ] 整体结构为 `{ "apps": [ ... ] }`（对应 `AppCatalogResponse`）
- [ ] JSON 字段名与上表完全一致
- [ ] `appId` / `packageName` 格式合法且在同一目录内分别唯一
- [ ] 任一必填身份字段、签名格式或重复约束非法时，客户端拒绝整份来源并走缓存/raw 回退
- [ ] `HIDDEN`/`REMOVED` 不进入首页/搜索/详情；`ROLLBACK` 用 `rollbackVersion` 覆盖展示版本并关升级态
- [ ] `rolloutPercent` + `allowedChannels` + `blockedChannels` 共同决定可见性

### 1.3 缓存策略（客户端已实现条件请求）
- [ ] 首次请求：200 + 完整 JSON → 解析、写缓存、展示
- [ ] 再次请求内容未变：304 + 空 Body → 复用本地缓存
- [ ] 内容已更新：200 + 新 JSON + 新 ETag/Last-Modified → 更新缓存刷新
- [ ] 请求失败（超时/5xx）→ 回退本地缓存
- [ ] 本地缓存不存在且请求失败 → 回退资源目录 `raw/app_store_catalog.json`
- [ ] 后端支持 `ETag`、`Last-Modified`、`Cache-Control`（至少 `max-age` 或 `no-cache`）

### 1.4 降级路径（三级回退：HTTP → 本地缓存 → 资源目录）
- [ ] 接口超时（>10s）回退本地缓存
- [ ] 本地缓存损坏回退资源目录
- [ ] 可选展示字段缺失不崩溃；身份必填字段非法时拒绝整份来源并回退
- [ ] 空目录 `{ "apps": [] }` 不崩溃（展示空列表页）
- [ ] 非法 JSON 不崩溃（回退缓存或资源目录）

### 1.5 鉴权
- [ ] 自定义请求头正常传递（`X-Client-Channel`、`X-Client-Platform` 等）
- [ ] 灰度标识通过请求头传递并被后端识别路由
- [ ] 鉴权失败返回 401/403，客户端回退缓存
- [ ] 请求头可按环境切换（开发/测试/生产，开发者设置切换）

## 二、OEM 车况信号联调清单（doc26 §2）

### 2.1 接入方式（客户端已预留接口）
- [ ] `VehicleStateSignalProvider` 的 OEM 实现可在设备获取驻车信号
- [ ] 提供驻车状态来源（P 档/驻车）
- [ ] 提供点火/电源状态来源（ACC ON/OFF）
- [ ] 提供行车/前后台限制来源
- [ ] 接入方式落地：广播 / Binder / SDK（任一）
- [ ] `observeVehicleState()` 返回实时 `StateFlow<VehicleRuntimeState>`
- [ ] `currentVehicleState()` 返回当前快照
- [ ] 在 `AppContainer` 中替换/装配 OEM 实现（业务层 `DefaultPolicyCenter`、页面层零改动）

广播型接入（无需写代码）：
- [ ] 配置 `CARAPPSTORE_OEM_VEHICLE_ACTION`、`CARAPPSTORE_OEM_PARKING_EXTRA`
- [ ] 可选配置 `CARAPPSTORE_OEM_POWER_EXTRA`

### 2.2 信号质量
- [ ] 信号延迟 < 500ms（车况变化 → `VehicleRuntimeState` 发射）
- [ ] 信号抖动容忍：策略状态 5 秒内不频繁切换
- [ ] 信号丢失回退安全默认值（驻车=false），不影响其他功能
- [ ] 首次信号：冷启动 3 秒内获取，超时用默认值
- [ ] 信号流连续性：`StateFlow` 不抛异常不完成

### 2.3 策略联动
- [ ] 驻车变化后页面实时刷新（拦截按钮自动变为可操作，无需手动刷新）
- [ ] 行车状态下 `canInstall()` 返回 false，升级同理被拦截
- [ ] OEM provider 异常时回退默认策略，客户端不崩溃
- [ ] 信号抖动不导致任务状态频繁闪烁
- [ ] Wi-Fi/存储信号与 OEM 信号独立，互不干扰

## 三、真机安装链路验收（doc26 §3）

### 3.1 安装器
- [ ] `PackageInstaller.Session` 正常创建（openSession 不抛异常）
- [ ] APK 数据经 `Session.openWrite()` 完整写入
- [ ] 用户确认页正常弹出（commit 后系统确认 Activity 弹出）
- [ ] 安装成功回调正确（IntentSender 收到 `STATUS_SUCCESS`）
- [ ] 安装失败回调正确（失败状态码 + 错误信息）
- [ ] 安装会话 ID 经 `InstallSessionStore` 持久化，强杀后可恢复
- [ ] 创建 Session 前核对 APK 包名、`versionCode` 和签名摘要
- [ ] 包名/版本/签名不匹配时不创建 Session，并返回对应 `APK_*` 失败码
- [ ] 成功回调后通过 PackageManager 核对实际包名和版本

### 3.2 OEM ROM 差异（逐车型记录）
- [ ] 系统确认页样式
- [ ] 确认页是否可自定义
- [ ] 安装成功回调码
- [ ] 安装失败回调码及含义
- [ ] 安装超时时间（如有）
- [ ] 静默安装是否支持
- [ ] 系统签名应用是否免确认
- [ ] 多用户/多空间安装行为
> 每款目标车型：装 APK → 触发完整安装并截图 → 测"确认/拒绝"两分支 → 记录回调码 → 强杀验证会话恢复。

## 四、真机全链路回归清单（doc25）

### 4.1 前置条件
- [ ] APK 已构建并安装到设备
- [ ] 应用冷启动无闪退
- [ ] 已选正确下载环境（开发者设置确认）
- [ ] 目录源可加载（网络连通或资源回退正常）
- [ ] 设备存储 >100MB 可用
- [ ] 日志工具（adb logcat / 车机调试口）就绪
- [ ] 网络抓包工具就绪（如需验证 HTTP）

### 4.2 下载链路（11 项）
- [ ] 小文件(<10MB)正常下载完成
- [ ] 大文件(>100MB)正常下载完成，无 ANR
- [ ] 下载暂停并恢复（断点续传，无回退）
- [ ] 下载取消并清理临时文件/元数据
- [ ] 断网后失败并自动标记
- [ ] 网络恢复后从断点续传
- [ ] 冷启动后恢复上次下载进度
- [ ] Range 分段合并正确（安装包可解析）
- [ ] SHA-256 校验通过进入安装
- [ ] SHA-256 校验失败标记错误、不进入安装
- [ ] 存储不足拒绝下载；重复点击不产生重复任务

### 4.3 安装链路（11 项）
- [ ] 正常安装完成，显示"安装成功"
- [ ] 系统确认页弹出并用户确认
- [ ] 安装成功后下载任务自动清理
- [ ] 用户拒绝确认 → 状态回退"可安装"，可重触发
- [ ] APK 损坏 → 安装失败正确回退，可重试
- [ ] 安装中断后会话持久化恢复
- [ ] 升级覆盖安装数据不丢失；降级安装被拦截
- [ ] APK 包名、版本代码和签名一致后才创建 Session
- [ ] APK 身份不匹配不弹系统安装页并清理不可复用下载产物
- [ ] 成功回调后 PackageManager 实际包名/版本一致才显示成功
- [ ] PackageManager 查询不到或事实不一致时记录校验失败，不误报成功

### 4.4 升级链路（7 项）
- [ ] 检测单个应用有升级
- [ ] 检测全部应用升级（checkAllUpgrades）
- [ ] 版本号相同不触发升级
- [ ] 单个应用升级成功（下载-校验-安装）
- [ ] 批量串行升级成功
- [ ] 批量中某个失败停止后续，已完成保持成功
- [ ] 升级失败后可重试

### 4.5 策略拦截（4 项）
- [ ] 非 Wi-Fi 拦截下载
- [ ] 存储不足拦截安装
- [ ] 行车状态拦截安装（**需 OEM 信号接入**，否则 N/A）
- [ ] 拦截提示文案正确且可操作（"当前非 Wi-Fi"/"存储不足"/"行车中暂不可操作"）

### 4.6 状态与页面（10 项）
- [ ] 首页列表加载（图标/名称/标签/简介）
- [ ] 搜索功能正常，结果匹配
- [ ] 详情页展示完整（描述/版本/大小/权限/评分/开发者）
- [ ] 详情页主操作按钮状态正确（下载/暂停/安装/打开/升级）
- [ ] 我的应用列表与 PackageManager 一致
- [ ] 我的应用升级角标正确
- [ ] 下载中心任务列表正确
- [ ] 安装中心任务列表正确
- [ ] 升级中心任务列表正确
- [ ] 进度实时更新、等待确认状态、错误可读可操作

### 4.7 异常场景（5 项）
- [ ] 强杀后冷启动状态恢复
- [ ] 快速连续点击（5+）不产生重复任务
- [ ] 同时下载安装不冲突
- [ ] 长时间后台(>30min)回前台状态正确
- [ ] 低内存/存储耗尽/系统时间篡改不崩溃
> 合计 44 项回归；记录模板见 `docs/25` §8。

## 五、联调门禁（doc26 §4.2，每阶段完成标志）

**第 1 周门禁（后端联调）**
- [ ] 200 返回目录正常解析并写缓存
- [ ] 304 返回复用缓存不重新解析
- [ ] 鉴权头正常注入并被后端识别
- [ ] 接口超时回退本地缓存
- [ ] 缓存不存在回退资源目录

**第 2 周门禁（OEM 信号）**
- [ ] `VehicleStateSignalProvider` OEM 实现可获取驻车信号
- [ ] 驻车信号变化策略 500ms 内刷新
- [ ] 行车状态安装/升级被拦截
- [ ] OEM provider 异常客户端不崩溃、回退默认

**第 3 周门禁（真机全链路）**
- [ ] docs/25 所有项 PASS 或 N/A（标记原因）
- [ ] 无 P0 缺陷，P1 ≤ 3 且有修复计划
- [ ] 每款目标机型至少一轮完整回归

**第 4 周门禁（灰度与稳定性）**
- [ ] 灰度请求头可按环境切换，后端正确路由
- [ ] 下发 `listingState`/`rolloutPercent`/channel 黑白名单后展示符合预期
- [ ] 连续运行 24h 无崩溃、无内存泄漏
- [ ] 批量升级 10 个应用无异常
- [ ] 弱网（丢包率 20%）仍可正常使用

## 六、问题升级路径（doc26 §4.3）

| 问题类型 | 负责方 | 升级条件 | 通道 |
|----------|--------|----------|------|
| 接口字段不匹配 | 后端 | 客户端无法解析或字段缺失 | 联调群 + 工单 |
| 缓存行为异常 | 后端 | 304 / ETag 处理异常 | 联调群 + 工单 |
| OEM 信号延迟/丢失 | OEM | 延迟 > 500ms 或信号中断 | 联调群 + 工单 |
| 安装器 ROM 差异 | OEM | 回调码/确认页与预期不符 | 联调群 + 工单 |
| 客户端崩溃/异常 | 客户端 | 回归中任何崩溃 | 内部 issue 跟踪 |
