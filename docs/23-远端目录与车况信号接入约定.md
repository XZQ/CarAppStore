# 23. 远端目录与可选平台信号接入约定

## 1. 目的

本文档用于说明当前 Android 客户端为“真实后端目录接入”和“可选平台信号接入”预留的接缝。CarAppStore 的产品定位是跨平台 App；OEM 车况只在车载发行目标中启用，详见 `docs/00-产品定位与平台边界.md`。

当前仓库已经完成：

- 商店目录 `HTTP -> 条件请求缓存 -> 资源目录` 回退链路
- 目录 DTO、HTTP request/response 与缓存元数据抽象
- 策略中心的实时信号提供者抽象
- 可选车载 OEM provider 的独立接入缝

因此后续接真实系统时，不应直接改页面或业务编排，而应优先替换 provider / client。

---

## 2. 远端目录接入点

### 2.1 当前结构

- `AppCatalogHttpClient`
- `AppCatalogHttpRequest`
- `AppCatalogHttpResponse`
- `HttpUrlConnectionAppCatalogHttpClient`
- `AppCatalogCacheMetadata`
- `AppCatalogCacheMetadataStore`
- `AppCatalogResponse`
- `AppCatalogItemResponse`
- `ResilientAppCatalogSource`
- `AppRemoteDataSource`

### 2.2 当前回退顺序

1. HTTP 拉取目录
2. 304 时复用本地缓存目录
3. `raw/app_store_catalog.json`

### 2.3 后端接入建议

优先保持接口字段与 `AppCatalogItemResponse` 对齐：

- `appId`
- `packageName`
- `name`
- `description`
- `versionName`
- `versionCode`：APK manifest 中的正数版本代码；除 Debug+LOCAL_SIM 外为安装必填字段
- `signerCertificateSha256`：允许签名证书的 SHA-256 摘要数组；除 Debug+LOCAL_SIM 外至少一项
- `category`
- `editorialTag`
- `recommendedReason`
- `searchKeywords`
- `developerName`
- `ratingText`
- `sizeText`
- `lastUpdatedText`
- `compatibilitySummary`
- `permissionsSummary`
- `updateSummary`
- `latestVersion`
- `hasUpgrade`
- `changelog`

如后端要求自定义鉴权或灰度头，优先通过 `DownloadEnvironmentConfig.catalogRequestHeaders` 注入，不要把认证逻辑散到页面或业务层。APK 签名摘要必须来自可信发布流水线，不能由客户端根据下载结果反向生成。

### 2.4 不建议的做法

- 不要在 `Fragment` / `ViewModel` 里直接请求目录接口
- 不要把接口字段映射逻辑散到 `AppManager`
- 不要绕过 `AppRemoteDataSource`

---

## 3. 可选车载平台信号接入点

本节不是通用 Android 版本的必选接入。当前代码已通过 `vehicleInstallPolicyEnabled` 在未启用车载能力时跳过驻车/行车门控；车载发行目标再按本节接入 OEM 真值。

### 3.1 当前结构

- `PolicyRuntimeSignalProvider`
- `AndroidPolicyRuntimeSignalProvider`
- `VehicleStateSignalProvider`
- `StaticVehicleStateSignalProvider`
- `PolicyRuntimeSignals`
- `DefaultPolicyCenter`

### 3.2 当前已接入信号

- Wi‑Fi 状态
- 低存储状态
- 可选 OEM 广播型车况接入：通过 `CARAPPSTORE_OEM_VEHICLE_ACTION`、`CARAPPSTORE_OEM_PARKING_EXTRA`、`CARAPPSTORE_OEM_POWER_EXTRA` 注入广播 action 和 extra 名称后启用

### 3.3 当前未接入信号

- OEM SDK / Binder 型真实车况 provider
- 更细的前后台限制

### 3.4 可选 OEM 接入建议

若某个车载发行目标能提供驻车或驾驶状态：

1. 如果 OEM 以广播提供信号，优先只配置 `CARAPPSTORE_OEM_*` 注入项，不改业务层。
2. 如果 OEM 以 SDK / Binder 提供信号，新增一个实现 `PolicyRuntimeSignalProvider` 或 `VehicleStateSignalProvider` 的 provider。
3. 在 `AppContainer` 中替换默认的 `StaticVehicleStateSignalProvider` 或复用当前广播装配。
4. 保持 `DefaultPolicyCenter` 不变。

### 3.5 不建议的做法

- 不要把 OEM 广播解析直接写进 `DefaultPolicyCenter`
- 不要让页面自己判断车况限制
- 不要让下载/安装/升级模块各自监听系统广播

---

## 4. 一句话总结

真实后端和可选平台适配器的推荐路径是：

**通用版本替换目录 client / 目录请求头并按平台启用能力；车载版本再装配 OEM 车况 provider，而不是把车况判断写进业务层或页面。**
