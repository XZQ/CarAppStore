## 1. 目录刷新与任务状态

页面同步系统已安装版本时，不再清空活动下载或覆盖安装阶段。目录升级可用性的刷新通过状态中心原子更新，只调整可用性，保留执行中的升级和需要重试的失败。执行者仍负责产生任务终态。

验证：`:business:testDebugUnitTest :business:testReleaseUnitTest`，两变体各 14 个测试类、118 项，0 失败、0 错误、0 跳过。

## 2. APK 失效与重新下载

安装失败只有在下载完成且仍有产物引用时才提供重试安装；产物失效则提供重新下载。APK 校验失败先将持久化下载任务标记失败、清空旧分片及续传标识，再回收 APK。重新下载受理后清除旧安装失败阶段，恢复暂停、继续及安装动作。

验证：business Debug / Release 各 120 项通过，0 失败、0 错误。

## 3. 安装和主动作异常边界

安装入口将目录读取、文件和持久化异常转为可重试的业务失败，保留有效 APK。主动作执行器统一反馈异常并继续传播协程取消；安装失败后不再继续读取升级信息。系统成功事件先确认安装版本，后续镜像写入失败只记诊断，不推翻系统事实。六个页面均接入共享状态反馈。

验证：全项目 Debug 329 项、Release 331 项通过，0 失败、0 错误。新增异常测试初次运行暴露了 JVM 测试替身没有覆盖 Android 日志方法的问题，补齐日志替身后完整门禁通过。

## 4. 系统安装与卸载事实

Repository 显式返回已安装列表和系统确认不存在的 appId。目录与镜像只提供包名映射；Android 11+ 缺少完整包可见性时不推断卸载。状态中心应用卸载事实前检查查询期间的状态变化及活动安装会话，保留下载与任务状态。壳层初始化和回到前台时刷新系统事实；打开失败会反馈原因并刷新，成功重试会清除旧反馈。

验证：全项目 Debug 336 / Release 338 项通过；最终业务层和数据层改动另行执行两变体测试通过。真实系统卸载与前台切换仍需设备验收。
