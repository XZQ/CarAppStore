## 1. 目录刷新与任务状态

页面同步系统已安装版本时，不再清空活动下载或覆盖安装阶段。目录升级可用性的刷新通过状态中心原子更新，只调整可用性，保留执行中的升级和需要重试的失败。执行者仍负责产生任务终态。

验证：`:business:testDebugUnitTest :business:testReleaseUnitTest`，两变体各 14 个测试类、118 项，0 失败、0 错误、0 跳过。

## 2. APK 失效与重新下载

安装失败只有在下载完成且仍有产物引用时才提供重试安装；产物失效则提供重新下载。APK 校验失败先将持久化下载任务标记失败、清空旧分片及续传标识，再回收 APK。重新下载受理后清除旧安装失败阶段，恢复暂停、继续及安装动作。

验证：business Debug / Release 各 120 项通过，0 失败、0 错误。

## 3. 安装和主动作异常边界

安装入口将目录读取、文件和持久化异常转为可重试的业务失败，保留有效 APK。主动作执行器统一反馈异常并继续传播协程取消；安装失败后不再继续读取升级信息。系统成功事件先确认安装版本，后续镜像写入失败只记诊断，不推翻系统事实。六个页面均接入共享状态反馈。

验证：全项目 Debug 329 项、Release 331 项通过，0 失败、0 错误。新增异常测试初次运行暴露了 JVM 测试替身没有覆盖 Android 日志方法的问题，补齐日志替身后完整门禁通过。

## 4. 系统安装与卸载事实

Repository 显式返回已安装列表和系统确认不存在的 appId。目录与镜像只提供包名映射；Android 11+ 缺少完整包可见性时不推断卸载。状态中心应用卸载事实前检查查询期间的状态变化及活动安装会话，保留下载与任务状态。壳层初始化和回到前台时刷新系统事实；打开失败会反馈原因并刷新，成功重试会清除旧反馈。

验证：全项目 Debug 336 / Release 338 项通过；最终业务层和数据层改动另行执行两变体测试通过。真实系统卸载与前台切换仍需设备验收。

## 5. 清理失败记录与安装就绪

清理安装失败只复位失败阶段，并在产物锁内执行。有效 APK 保持下载完成，安装状态恢复为非活动状态；真实 WAITING 安装阶段禁止重复主动作。无效 APK 的文件、分片和任务记录一并回收。保留已有安装版本，不把升级失败清理误当成卸载。

验证：business 两变体各 131 项通过。跨安装/下载管理器回归确认：清理失败后，完成任务清理返回 1，APK 与任务记录均删除。

## 6. 安装后的产物回收

安装成功后先删除 APK，再删除下载任务记录。文件删除失败时保留完成任务、路径和清理反馈，缓存统计仍能发现文件；下载管理器恢复后可再次清理。任务元数据删除失败也不推翻系统安装成功事实，不恢复已经删除的 APK 引用。

验证：business 两变体各 133 项通过。新增跨管理器回归验证未删除的 1024 字节 APK 在恢复后仍被统计，重试后文件和任务删除、统计归零，已安装版本保留。

## 9. 运行时短期鉴权

BuildConfig 移除固定认证值，生产门禁拒绝旧固定认证配置。目录与 CDN 分别使用内存中的短期 Bearer 凭证，绑定 HTTPS origin、最长 15 分钟、提前 30 秒停止使用，并以单调时钟限制存续时间。每次 HTTP 请求读取最新值；目录错误诊断只记录状态码，避免响应正文回显凭证。发布配置、模板和相关验收文档已同步；具体边界和剩余服务接入见 [运行时短期鉴权接入](35-运行时短期鉴权接入.md)。

验证：全项目 Debug 350 / Release 352 项通过。新增凭证边界及 HTTP loopback 用例覆盖更新、过期、清除、时钟回拨、跨 origin、注入与错误正文。两个生成的 BuildConfig 均无固定鉴权字段。临时证书的 `assembleProductionRelease` 与 apksigner 校验通过；两种模式配置正向通过，旧固定认证值按预期被拒绝。临时签名仅为本地工程验证；无后端接口资料，登录、签发、刷新和生产服务联调未执行。

## 10. Lint 与平台存储适配

目录排名改为资源格式化，按当前 Locale 显示数字；系统设置 URI 使用现有 KTX。下载器必须显式注入目录空间查询，由 AndroidStorageInfoProvider 同时服务策略预检、分片目录和最终 APK 目录。策略预检取系统可分配量与实际可写量的较小值，系统查询失败退回实际可写量；下载每 MiB 的高频复查只读文件系统，避免反复跨进程查询。无效目录返回零。未调用 allocateBytes，不把尚未回收的系统缓存算作已经可写的空间。

桌面 `sw900dp-land` 使用侧栏，未声明手机和平板的 `bottomNav`；MainActivity 使用可空访问，现有 ShellCompatibilityTest 覆盖桌面侧栏。保留这一合法布局差异产生的 InconsistentLayout 提示，不增加占位控件或关闭检查。
