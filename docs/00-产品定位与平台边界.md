# 00. 产品定位与平台边界

## 1. 一句话定位

CarAppStore 是一个**跨平台应用分发与管理 App**。产品能力面向手机、平板、桌面级大屏和其他可接入终端复用；车载设备只是可选平台形态之一，不是产品定义，也不是通用版本成立的前提。

## 2. 产品与当前仓库的边界

| 层级 | 当前定义 |
| --- | --- |
| 产品 | 跨平台应用目录、下载、安装、升级、应用管理、状态、策略和任务中心 |
| 当前仓库 | Android/Kotlin 客户端实现，最低 API 26 |
| UI 形态 | 紧凑屏、平板/中屏、桌面级大屏/横屏；同一业务状态和页面能力按窗口尺寸适配 |
| 平台能力 | 网络、存储、安装器、文件系统和生命周期等能力通过接口或系统桥接层接入 |
| 可选扩展 | 车载 OEM 车况、驻车、电源和特定 ROM 安装服务；只对启用该适配器的发行目标生效 |
| 尚未包含 | iOS、Windows、macOS、Linux 或 Web 的独立客户端工程；不能把产品的跨平台定位写成这些客户端已经交付 |

“跨平台”描述产品边界和架构方向；“Android”描述这个仓库当前可构建、可测试的客户端实现。两者不能互相替代。

## 3. 通用主线与平台适配层

所有平台共享的产品主线是：

1. 应用目录与搜索展示。
2. 下载、校验、安装和升级任务管理。
3. 已安装应用、状态中心、策略中心和任务中心。
4. 缓存、恢复、失败可见性、事件记录和生产环境隔离。
5. 按窗口尺寸适配的多终端 UI。

平台差异必须收口在适配层：

- Android 当前使用 `PackageInstaller`、`PackageManager`、系统网络与存储信号。
- `layout/`、`layout-sw600dp/`、`layout-sw900dp-land/` 表示紧凑、中等和扩展窗口布局，不等同于三个独立产品。
- `VehicleStateSignalProvider`、`BroadcastVehicleStateSignalProvider` 和 `CARAPPSTORE_OEM_*` 是历史上已实现的**可选车载适配器**。
- OEM、驻车、行车和车机 ROM 验收不得放进通用发布门禁；只有声明支持车载目标的发行版本才执行这些专项检查。

## 4. 当前实现需要保留的事实

- 包名、模块名和 `CarAppStore` 工程名暂不因产品定位修正而变更。
- 当前代码仍保留 `VehicleStateSignalProvider`、`parkingMode` 等车载命名和默认策略。这是现有实现事实，不代表产品只服务车端。
- 面向非车载平台发布前，应把驻车策略改成能力开关或平台策略插件；未启用车载能力时，不应因为缺少 OEM 信号阻断通用安装/升级流程。
- 本次文档修正不宣称上述代码解耦已经完成；相关工作应作为跨平台商用化任务单独实现和验证。

## 5. 文档术语规范

| 避免作为项目总称 | 统一表述 |
| --- | --- |
| 车载应用商店、车端 App、面向车机场景 | 跨平台应用分发与管理 App |
| 车机/桌面端 | 桌面级大屏/扩展窗口；车载横屏是可选适配场景 |
| OEM 联调是上线前必需项 | OEM 联调是车载发行目标的专项门禁 |
| 真机仅指车机 | Android 真实设备；按手机、平板、大屏及可选车载目标分别记录 |

历史文件名中保留的“车况”“OEM”用于兼容既有链接；应以文件正文的新标题和本定位文档解释其适用范围。

## 6. 验收分层

### 通用 Android 基线

- 手机、平板和桌面级大屏/横屏窗口布局。
- 目录、下载、APK 身份校验、安装、升级、恢复和错误状态。
- Android 版本、ROM、包可见性、未知来源安装权限和生命周期差异。
- 生产后端、CDN、签名、事件上传和隐私合规。

### 可选车载平台专项

- OEM 驻车、行车、电源或前后台限制信号。
- 车载 ROM 安装确认页、回调码和专用安装服务。
- 驾驶场景交互限制、远距离阅读和车规触控要求。

只有发行目标明确包含车载平台时，第二组才是发布门禁。
