## 2. 一句话现状

仓库内 Android 主链路、工程分层、多终端 UI 壳层、本地目录回退、下载/安装/升级状态机、策略门控、平台分流、事件落盘、Release 构建入口和生产目录/CDN/认证/签名门禁都已完成。默认驻车语义已改为可选车载能力，其他平台安装包也会在展示与执行层关闭；剩余通用工作主要是注入真实生产值、观测平台和 Android 设备矩阵验收。

## 3. 本地已完成

- 多模块结构：`app / common / core / data / business / feature-*` 已稳定。
- 页面范围：首页、搜索、详情、我的应用、下载中心、安装中心、升级中心、开发者设置均已接入。
- 多终端 UI：手机、平板、桌面级大屏/扩展窗口资源限定符壳层已具备；扩展窗口含侧边导航和任务摘要，车载横屏可按需复用。
- Repository：生产实现为 `RealAppRepository`；`FakeAppRepository` 仅用于测试。
- 远端目录链路：支持 `HTTP -> 本地缓存 -> raw 资源` 回退、ETag / Last-Modified 条件请求、鉴权头和环境变量注入。
- 下载链路：真实 HTTP、Range、分片、校验、断点续传、暂停/取消、失败恢复。
- 下载路径安全：目录标识和任务 ID 白名单、重复项拒绝、任务目录 canonical path containment。
- 安装链路：APK 包名/版本/签名预检、`PackageInstaller.Session`、用户确认页分发、安装会话持久化和安装后 PackageManager 事实核对。
- 升级链路：批量检测、串行升级、策略门控、失败重试。
- 策略链路：Wi‑Fi、存储与可选驻车/车况策略已接入；只有 OEM 配置完整时才启用车载驻车限制。
- 平台链路：目录解析 `supportedPlatforms`，Android 客户端以 `currentPlatform=ANDROID` 计算动作；其他平台产物在下载、安装和升级入口统一拒绝。
- 图片链路：`asset://`、`file://`、`http(s)://` 图标、头图、截图加载与文本兜底。
- 运营治理：灰度、黑白名单、隐藏/下架、回滚版本本地过滤。
- 观测入口：页面曝光、主动作、下载/安装/升级开始与结果本地事件落盘。
- Release 入口：`verifyProductionConfig` 会校验 HTTPS 端点、认证模式并实际解锁 keystore/alias；`assembleProductionRelease` 构建签名 APK，仓库不保存密钥。
- CDN 认证：支持目录下发短时签名 URL 与运行时短期凭据（`RUNTIME`）；旧的固定 `*_AUTH_HEADER` / `*_AUTH_VALUE` 配置已被 `verifyProductionConfig` 明确拒绝，令牌不得通过构建配置注入，详见 [运行时短期鉴权接入](35-运行时短期鉴权接入.md)。
- 设备证据：`collect-android-baseline.ps1` 在恰好一台已授权设备上采集型号、API、构建指纹、屏幕、APK 摘要和可选安装结果，不能替代 docs/25 手工回归。
- Release 环境：非 Debug 构建固定使用 PROD，忽略历史调试环境选择；release raw 目录为空，不携带 LOCAL_SIM 的 `10.0.2.2` APK 地址。
- 目录一致性：可见目录的内存缓存以「请求指纹（含灰度头）+ 数据来源」为键，远端结果 30s、磁盘/内置降级结果 3s；Android 条目缺正数 `versionCode` 或签名摘要在非 Debug+LOCAL_SIM 环境直接判目录不可信。
- 失败收敛：安装失败区分环境类（`POLICY_BLOCKED` 保留重试）与终态类（产物不一致转重新下载，平台/系统能力缺失置灰）；升级流程在下载与安装等待期间复查策略，失败收敛时消费 staged 目标版本。
- 埋点重试：`EventTracker` 用有界队列（200 条，超出丢最旧）保留未被上报通道接收的事件，下一次上报整批重试。
- 恢复边界：同一 JSON 文件的多个 `VersionedJsonStore` 实例共享固定 64 条进程锁带；读到比当前程序更高的 schema（用户回退安装旧版本）时按原样返回且不回写，`update()` 覆盖前先备份为 `<name>.newer-schema`；冷启动会以 PackageManager 事实和本应用平台 Session 对账安装记录。
- CI：`.github/workflows/android-ci.yml` 已覆盖 JDK 21 单测、编译、Lint、Debug/Release APK 和验证产物归档；首次远端 hosted runner 运行已经成功。

## 5. 仍未完成

以下事项需要真实外部资源或目标设备：

- 真实后端目录 API：正式地址、鉴权、`supportedPlatforms`、灰度头、错误码和缓存协议。
- 真实 APK 下载源：CDN 域名、包体文件、checksum 类型和值、正数 `versionCode`、签名证书 SHA-256 摘要和灰度策略。
- Android 设备安装验收：手机、平板和桌面级大屏上的 Android 版本/ROM 确认页、回调码、权限行为和失败恢复。
- 可选车载 OEM 车况信号：只有车载发行目标才需要目标 SDK、系统广播或 provider 协议。
- 生产签名真实值：keystore、alias、密码由安全环境注入；仓库门禁和临时测试证书验证已经完成。
- 运营观测平台：事件上传服务、隐私字段、告警看板和失败归因。

### 构建环境（换机时最先确认）

JDK 21、Android SDK Platform 36 和 SDK 路径属于**本机工具链**，不随仓库分发。执行 `python tools/verification/check_build_env.py` 可逐项诊断，失败项会给出安装 / 配置命令。自检未通过时直接运行 `gradlew` 只会以 `SDK location not found` 或 JDK 版本错误收场。CI 通过 `setup-java` + `setup-android` 自行准备环境，不依赖任何开发机。

## 7. 换机后的推荐动作

1. 拉取 `origin/main` 并确认工作区干净。
2. 运行 `python tools/verification/check_build_env.py` 自检；按提示配置 JDK 21、Android SDK Platform 36 与 SDK 路径（`ANDROID_HOME` 或 `local.properties`）。自检失败时不要直接跑 `gradlew`。
3. 跑 `testDebugUnitTest`、`compileDebugKotlin`、`lintDebug`、`assembleDebug`。
4. 普通工程产物可跑 `:app:assembleRelease`；可分发产物必须运行 `tools/production/verify-production-readiness.ps1`。
5. 若接真实环境，按 `docs/33` 注入安全值并生成签名 APK，再按 `docs/25` 做设备矩阵回归。

## 8. 不要误判的边界

- 默认目录和默认 APK 地址仍是示例/回退值，不代表已接真实生产后端。
- Debug + LOCAL_SIM 只允许缺少版本代码/签名元数据；包名以及已提供但不匹配的版本或签名仍会严格拒绝。
- unsigned release APK 只证明 release 构建链路可生成；临时测试签名也只证明门禁有效，不等于正式生产证书已经注入。
- OEM 广播接入点已具备，但它只服务可选车载发行目标；通用版本不应等待真实车机协议。
- 本地事件日志已具备，上传和看板仍属于外部平台工作。
- 仓库内 `AGENTS.md` / `CLAUDE.md` 自包含，不引用任何特定用户目录；历史计划文档中的 `C:\Users\XZQ\...` 只是当时机器的执行记录，不是当前环境要求。
- 本机（Windows）运行 `:core:testDebugUnitTest` 全量时有 27 条 `RealFileDownloaderTest` 失败，属本机裸 socket 测试设施的预置问题（JDK 17 下同样失败），不是代码缺陷；判断下载器行为请跑 CI 或目标测试，不要据此改动下载实现。
- 旧的固定 `*_AUTH_HEADER` / `*_AUTH_VALUE` 构建配置已被生产门禁拒绝；看到早期文档提到"固定 Header 可用"时以 `build.gradle.kts` 和 docs/35 为准。
