# 运行时短期鉴权接入

当前客户端不再将目录或 CDN 的认证值编入 BuildConfig。此文描述已经接入 HTTP 链路的凭证边界，以及仍需要后端完成的登录和会话协议；不代表生产认证已经联调。

## 可用模式

| 配置 | 值 | 行为 |
| --- | --- | --- |
| `CARAPPSTORE_CATALOG_AUTH_MODE` | `PUBLIC` | 公开、只读目录，不发送 Bearer 凭证；不得将其用于需要身份保护的目录 |
| `CARAPPSTORE_CATALOG_AUTH_MODE` | `RUNTIME` | 请求时读取目录的内存短期凭证；缺失或过期时拒绝发起该网络请求 |
| `CARAPPSTORE_DOWNLOAD_AUTH_MODE` | `SIGNED_URL` | 使用目录下发的短时签名 HTTPS APK URL，不附加固定认证值 |
| `CARAPPSTORE_DOWNLOAD_AUTH_MODE` | `RUNTIME` | 每次 HEAD、GET、Range 请求读取 CDN 的内存短期凭证 |

上述开关用于 PROD 环境；测试真实认证时应以专用测试服务地址配置 PROD 发行目标。公开客户端渠道和平台标识可以保留在请求头，但不能作为访问授权。

## 已实现的客户端边界

- `AppContainer.catalogCredentials` 和 `downloadCredentials` 分开管理目录与 CDN 的授权；登录接入层调用 `authorize(token, expiresAtMillis)`，登出或撤销时调用 `clear()`。
- 凭证只驻留内存，不进入 SharedPreferences、JSON、日志、ViewModel SavedState 或 APK 构建常量。进程重启后需要重新建立授权。
- 默认接受剩余有效期大于 30 秒、最长 15 分钟的 Bearer token，提前 30 秒停止使用；同时检查单调时间，系统时钟回拨不会延长有效期。
- 凭证绑定配置中的 HTTPS origin（域名和端口），不允许发往其他 origin；携带认证头的请求不自动重定向。
- 每次请求都重新读取凭证，登录接入层更新后，后续请求自动使用新值。
- 拒绝非法 token 格式、过长 token、换行注入和非 HTTPS 目标；诊断字符串不输出 token，目录 HTTP 错误也不输出可能回显凭证的响应正文。
- `verifyProductionConfig` 拒绝旧的 `*_AUTH_HEADER` / `*_AUTH_VALUE` 固定配置，并校验新模式。配置格式通过不能证明登录/刷新协议可用。

## 后端接入仍需完成

目前未提供后端仓库、认证接口或测试账号，因此没有实现或假定任何登录、令牌签发和刷新 HTTP 接口。发布前需要确认：

1. 身份来源、原生客户端登录协议、签发与刷新端点。客户端不得持有服务端主密钥或用内置静态密钥换取高权限令牌。
2. 目录和 CDN 的 audience、权限范围、TTL、撤销方式，以及 401/403 的刷新或重新登录行为。接入层负责有界重试和刷新去重，不应在每个 Range 请求中独立登录。
3. 成功建立会话后将两个 audience 的结果分别交给上述 `authorize` 接口；在到期前主动刷新，并在认证失效或退出账号时清除相关凭证。
4. 若使用签名 URL，服务端必须约束应用、版本、路径、有效期和可用操作；过期后客户端需要重新获取目录或下载授权，不能通过修改 URL 参数自行续期。
5. 在真实 TLS 服务及 Android 设备上验证续传期间凭证更新、401/403、失效、退出账号、冷启动与签名 URL 过期。

仓库的测试使用明确的测试字符串和 loopback HTTP，仅证明客户端请求接线及失效边界。生产服务验收仍为 **NOT RUN**。

## 从旧配置迁移

删除发布环境中的 `CARAPPSTORE_CATALOG_AUTH_HEADER`、`CARAPPSTORE_CATALOG_AUTH_VALUE`、`CARAPPSTORE_DOWNLOAD_AUTH_HEADER` 和 `CARAPPSTORE_DOWNLOAD_AUTH_VALUE`。将 `HEADER` 下载模式迁移为 `RUNTIME`，并先完成可信会话接入；公开目录才可选择 `PUBLIC`。没有会话接入时不得把受保护的目录改成公开访问来绕过鉴权。

Release 签名私钥和密码继续通过受控发布环境提供，只供签名工具使用，不进入客户端代码。
