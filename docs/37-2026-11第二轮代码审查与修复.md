# 2026-11 第二轮代码审查与修复

> 审查方式：只读静态审查（下载 / 安装升级 / 数据与 UI 三条链路并行），发现逐条回源码复核后修复。
> 执行环境限制：本机无 JDK 17 / Android SDK，本地未跑 Gradle 门禁；编译与单测以远端 CI（对应 SHA 的 Actions 产物）为准。
> 本文档只记录本轮确认的缺陷与修复点，不重复 docs/36 的既有结论。

## 修复清单（P1 真实缺陷）

| # | 位置 | 问题 | 修复 |
| --- | --- | --- | --- |
| 1 | `core/storage/VersionedJsonStore.kt` | 损坏 / 半写 JSON 被静默吞掉并回退默认空根，下次 `update()` 把空数据写回原文件，本地记录（任务、会话、分片）静默全量丢失 | 解析失败时先把损坏文件隔离备份为 `<name>.corrupted`（保留一代）再按空数据处理；rename 失败时退化为「复制现场 + 删除主文件」，避免每次读取重复隔离；纯 `read()` 不回写覆盖现场 |
| 2 | 同上 | `ATOMIC_MOVE` 失败回退 `copyTo+delete` 非原子；父目录 fsync 用 `FileOutputStream(目录)` 在 Android/Linux 必抛 `EISDIR` 且被吞 | 回退改为同目录 `Files.move(REPLACE_EXISTING)`（POSIX rename / Windows MoveFileEx 同卷原子）；目录 fsync 改用只读 `FileChannel.force`，Windows 不支持时保持尽力而为 |
| 3 | `business/domain/state/DefaultStateCenter.kt` | 系统已安装但本地记录 `FAILED` 时，`syncInstalled` 只在 `NOT_INSTALLED` 时改写，UI 永久显示「安装失败」，周期刷新无法纠正 | 系统事实优先：遗留 `FAILED` 记录收敛为 `INSTALLED` 并清理随失败遗留的错误；进行中的任务（WAITING/INSTALLING/PENDING_USER_ACTION）仍只刷新版本 |
| 4 | `business/upgrade/DefaultUpgradeManager.kt` | 批量升级中某应用已有单任务升级在执行时 `tryLock` 失败被静默跳过，随后按状态误判失败并中断整批 | 拆分 `startUpgradeExclusive` 返回是否真正获得执行权；批量循环对「执行中去重」记为 skipped（升级中）并继续后续应用 |
| 5 | `core/downloader/RealFileDownloader.kt` | RUNTIME 短期鉴权模式禁止自动重定向但无手动跟随，CDN 3xx 直接判失败 | 所有请求统一禁用 JDK 自动重定向、改由 `openConnection` 手动逐跳跟随（301/302/303/307/308，上限 5 次）；固定头按 `sameOrigin` 只在同源跳发送，动态凭证每跳经 `requestHeadersProvider` 重新计算并由提供器拒绝跨 origin；每跳都校验 `Location` 协议、响应停止请求，不会因跨 origin 后请求头变空而退回自动跟随 |
| 6 | 同上 | 分片写盘失败（ENOSPC、只读文件系统等）落入统一 `IOException` 出口被归类为可重试 `NETWORK_INTERRUPTED`，`STORAGE_IO` 全仓零引用 | 写盘路径（建文件 / 截断 / 打开定位 / 写入）统一包装为 `SegmentWriteIOException`，识别 ENOSPC 归类为不可重试 `STORAGE_INSUFFICIENT`，其余归类为可重试 `STORAGE_IO`；新增仅测试使用的 `beforeSegmentWriteHook` 注入点（与既有 `beforeMergeHook` 同风格），避免依赖文件系统权限构造不稳定用例 |
| 7 | `core/downloader/FileDownloader.kt` + `RealFileDownloader.kt` | `PAUSED` 无法升级为 `CANCELED`：暂停后立即取消时，收尾协程把持久化记录与页面状态覆盖回暂停，APK/分片也不清理；合并阶段先写整包再检查停止 | 停止原因允许 `PAUSED → CANCELED` 单向升级；合并前增加停止检查，合并期间收到停止时删除未校验的合并产物（分片保留，恢复后重新合并） |

## 新增 / 更新测试

- `VersionedJsonStoreTest`：损坏文件隔离备份、损坏后 `update` 保留备份、连续损坏只保留一代（+3）。
- `DefaultStateCenterTest`：安装事实收敛遗留失败记录、不打断进行中安装；原「fact refresh preserves failed task」拆分重写为升级维度语义（+2，改 1）。
- `DefaultUpgradeManagerTest`：批量遇到执行中同应用任务时跳过并继续后续（+1）。
- `DefaultDownloadManagerTest`：`ControllableFileDownloader` 增加停止发射门闩；新增「pause 后 cancel 升级停止原因并最终落盘为已取消」（+1）。
- `RealFileDownloaderTest`：`TestHttpServer` 增加按路径 302 重定向能力；新增同源重定向跟随并逐跳携带凭证、跨 origin 拒绝转发、重定向超上限失败、写盘失败归类 `STORAGE_IO`（+4）。

## 明确不改的边界

- `assembleRelease` 不跑 `verifyProductionConfig` 是有意设计（README：可分发产物走 `assembleProductionRelease`），不是缺陷。
- docs/21 中 StateCenter 分流、Room 迁移、`org.json → kotlinx`、深拷贝优化属「需真机 trace 证明收益」的有意搁置项。
- 鉴权过期 / 跨 origin 拒绝目前归类为 `NETWORK_INTERRUPTED` 上报（错误文案准确、可重试语义可接受）；如需独立的 `AUTH_EXPIRED` 失败码，连同重认证 UX 一起规划，不在本轮范围。
- 埋点上传服务、设备矩阵、正式签名、真实目录 / CDN 仍属外部条件，与 docs/36 结论一致。
