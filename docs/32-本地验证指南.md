# 本地验证指南：本地模拟环境跑通完整下载流程

本文档说明如何在本机（Android Studio + 模拟器/真机）把 CarAppStore 跑起来，使用 `LOCAL_SIM`（本地模拟）环境加载 10 个开源 App，并验证「浏览 → 详情 → 下载（最多 3 并发）→ 进度/暂停续传 → 安装」的主链路。

CarAppStore 的产品定位是跨平台 App；本指南只验证当前仓库的 Android 客户端。模拟器/手机/平板/桌面级大屏均属于通用验证范围，车载设备和 OEM 车况不是 LOCAL_SIM 的前置条件。

> 2026-07-31 已在 JDK 17、compileSdk/targetSdk 36 下通过命令行 `testDebugUnitTest`、`compileDebugKotlin`、`lintDebug`、`:app:assembleDebug` 与 `:app:assembleRelease`；45 份测试报告共 247 个测试且无失败，13 份 Lint 报告为 0 告警、0 错误。本地模拟仍须在模拟器/设备上完成联网、下载和安装确认页的人工验收。

---

## 1. 前置条件

- Android Studio（Hedgehog+/2023.1+ 均可）
- JDK 17（AGP 8.x 要求；本机可用 JetBrains Runtime 17 或 Oracle/Temurin 17）
- Android SDK Platform 34+，且已安装 **Android Emulator**
- Python 3.10+（仅用于运行仓库跟踪的 `tools/local-sim/` 工具；APK 资产仍放在已忽略的 `local-apks/`）

## 2. 准备并启动本地 APK / 目录服务器

APK 与目录 JSON 已落在 `local-apks/` 目录（共 10 个开源 App，约 118 MB）。需要起一个支持 `Range` 的静态服务器，供 App 走分片下载 + 断点续传。

```bash
cd CarAppStore
python tools/local-sim/generate_catalog.py
python tools/local-sim/test_generate_catalog.py
python tools/local-sim/serve.py
# 输出：Serving ... on http://0.0.0.0:8080
# 模拟器访问地址：http://10.0.2.2:8080
```

- 端口 `8080`，监听 `0.0.0.0`
- 支持 `Range` 请求（返回 `206 Partial Content`），匹配 `RealFileDownloader` 的分片下载
- 目录根自动提供 `catalog.json`（由 `generate_catalog.py` 生成，文件名中的版本号会写入 `versionCode`，并同步到 `data/src/main/res/raw/app_store_catalog.json` 兜底）

> 必须保持此服务器运行，否则 App 内下载会失败（APK 地址指向 `10.0.2.2:8080`）。

## 3. 切到本地模拟环境（LOCAL_SIM）

Debug 构建内置 4 套环境（DEV / TEST / PROD / **LOCAL_SIM**）。LOCAL_SIM 的目录与 APK 均来自上面的本地服务器；Release 构建固定使用 PROD，忽略历史调试选择，并通过 `data/src/release/res/raw/app_store_catalog.json` 提供安全空目录，不携带本地模拟 APK 地址。

1. 在 App 内进入「开发者设置」（一般位于侧边菜单或设置页；扩展窗口可从右下角调试入口进入）
2. 点击「切到本地模拟」按钮
3. 应用会重启以重新创建依赖容器；重启后确认提示文案变为：`本地模拟环境：目录与 APK 来自本机静态服务器…`

代码接线（供参考）：
- `DownloadEnvironmentConfig.forEnvironment(LOCAL_SIM)` 生成配置：`catalogEndpointUrl = http://10.0.2.2:8080/catalog.json`，`downloadBaseUrl = http://10.0.2.2:8080`，`defaultSourcePolicy = DIRECT_HTTP`
- `AppRemoteDataSource` 先试 HTTP 目录，失败回退 `R.raw.app_store_catalog`（raw 兜底，已同步 10 App）

## 4. 运行 App 并验证主链路

1. Android Studio 打开 `CarAppStore` 项目，Sync Gradle（用 JDK 17）
2. 选 `app` 模块，Run 到模拟器（建议 API 35/36）或已连接真机
3. 按以下路径验证：

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 首页浏览「青柠应用商店」 | 看到 10 个开源 App 卡片（名称/版本/图标占位首字） |
| 2 | 点任一卡片 → 详情页 | 应用信息面板 + 任务状态面板 + 下载/暂停/取消按钮 |
| 3 | 点「下载」 | 进入下载，进度条递增；**同时发起 >3 个下载时，第 4 个起排队 WAITING**（并发上限 3，见 `DefaultDownloadManager` 的 `Semaphore(3)`） |
| 4 | 下载中途点「暂停」 | 进度停止；再点「继续」从断点续传（Range 生效） |
| 5 | 下载中心页 | 列表展示各任务状态/进度/速度；空态、失败态有独立面板 |
| 6 | 升级中心 / 安装中心 | 复用同一套任务中心组件，列表与状态正常；下载完成后，若未授予“允许安装未知应用”权限，横幅可跳转到系统授权页 |
| 7 | 搜索页 | 输入关键词过滤 10 App，结果列表正常 |

> Debug 的 `LOCAL_SIM` 会提供“已驻车”车况，并允许目录缺少签名摘要，仅用于本地下载/安装联调；包名和已提供的版本/签名仍必须匹配。其他环境缺少正数 `versionCode` 或签名摘要时会在创建 Session 前失败关闭。安装会打开系统 `PackageInstaller` 确认页，需由用户在设备上完成授权与确认。

## 5. 数据来源说明

- 10 个 App 清单见 `docs/31-UI补全与下载联调计划.md` 附录「本地模拟 10 App 记录」
- 目录字段与 `AppCatalogItemResponse` 对齐：`sourcePolicy=DIRECT_HTTP`、`listingState=ACTIVE`、文件 SHA-256 和 `versionCode` 全填；本地模拟签名摘要可为空
- 包名示例：Aurora 商店、开源计算器、Fossify 日历/时钟/联系人/文件管理/图库/笔记、极简手电筒、F-Droid

## 6. 常见问题

- **下载一直失败**：检查 `serve.py` 是否在运行；模拟器用 `10.0.2.2:8080`（不是 `localhost`）。
- **目录为空**：确认已切到 LOCAL_SIM；检查服务器和 `catalog.json`，并从仓库根目录重跑 `python tools/local-sim/generate_catalog.py`。
- **安装被拦截**：在系统设置中为本应用授予“允许安装未知应用”，然后回到应用重试。
- **APK 身份校验失败**：确认 APK 文件名版本与目录 `versionCode` 一致、包名未变；非 LOCAL_SIM 还必须提供实际签名证书 SHA-256 摘要。

## 7. 三类窗口验证

- **手机**（默认 `layout/`）：底部 4 项导航 + 单列卡片
- **平板**（`layout-sw600dp`，全部 6 个业务页均已补齐双列布局）：双列 + 底部导航
- **桌面级大屏/扩展窗口**（`layout-sw900dp-land`）：左侧完整菜单 + 右侧常驻任务摘要；车载横屏可按需复用

切到不同屏幕尺寸（或旋转为横屏）即可验证三类窗口壳层与布局断点。首页/详情/搜索/我的应用/下载中心/安装中心/升级中心 7 个页面均已具备 phone + sw600dp + sw900dp-land 三套布局。

## 8. 本阶段新增 UI 验证要点（P1/P2）

### 8.1 策略拦截独立卡片（详情页 · P1 #18）
- 触发：使当前策略不满足下载条件（如未连 Wi‑Fi / 低存储模式；启用车载能力时还可使用未驻车状态），进入任意应用详情页。
- 预期：应用信息面板底部出现「策略拦截提示」卡片（`ui_policy_intercept_title`），展示具体拦截原因文案，并带「去策略设置」按钮。
- 点击「去策略设置」→ 跳转开发者设置页，并打点 `policy_intercept_open_settings`（可在埋点看板查看）。
- 实现：`PolicyCenter.canDownload(appId)` 在 `DetailViewModel` 中计算原因，写入 `DetailUiState.interceptReason`，由 `DetailFragment` 渲染 `include_detail_app_info` 中的 `view_policy_intercept` 卡片。

### 8.2 埋点看板（开发者设置 · P2）
- 入口：开发者设置页新增「埋点看板」面板。
- 预期：读取本地 `event_log.tsv`，统计各类型打点次数（下载/安装/升级/页面浏览/策略等归一化分类），展示总数与 Top 8 分类；点「刷新看板」重算。
- 事件归一化：末尾为包名的尾段（含 `.`）会被剥离，例如 `download_start_com.aurora.store` → `download_start`，便于按业务动作聚合。
- 实现：`DeveloperSettingsFragment.bindAnalyticsSection()` / `renderAnalytics()` / `normalizeEventCategory()`。

### 8.3 灰度头（开发者设置 · P2）
- 入口：开发者设置页新增「灰度头」面板。
- 预期：开关「启用灰度头」+ 标识输入框（如 `user-123` / `bucket-A`），点「应用灰度头」持久化（SharedPreferences `car_app_store_grayscale`），当前展示更新；「清除灰度头」恢复空态。
- 该标识作为目录请求灰度头下发的取值，用于后续按 `rolloutPercent` / `listingState` 过滤可见应用（目录层接线为后续接入项）。
- 实现：`DeveloperSettingsFragment.bindGrayscaleSection()` / `loadGrayscaleHeader()` / `saveGrayscaleHeader()`。
